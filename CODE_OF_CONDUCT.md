# Code of Conduct

## Our commitment

The Blog Management System project welcomes participation from people with different backgrounds, experience levels, and perspectives. We want project spaces to remain respectful, accessible, and focused on constructive work.

## Expected behavior

- Be considerate and respectful in discussions, reviews, issues, and contributions.
- Critique ideas and code directly without attacking the person who shared them.
- Make room for different viewpoints and accept feedback in good faith.
- Use inclusive language and respect people's names, identities, and boundaries.
- Protect private information. Share only data you have permission to disclose, and remove personal or secret values from examples and logs.
- Help keep technical discussions focused on the project and its users.

## Unacceptable behavior

Harassment, discrimination, threats, intimidation, personal attacks, sustained disruptive behavior, sexualized attention without consent, doxxing, and publishing another person's private information are not acceptable. Deliberately sharing credentials, private user content, or other sensitive data is also prohibited.

## Scope

This policy applies in project spaces, including the GitHub repository, issues, pull requests, code reviews, and other channels used to discuss or maintain this project. It also applies when someone is representing the project in a public setting.

## Reporting and enforcement

Report conduct concerns privately to maintainer Brajesh Kumar through the [project maintainer's GitHub profile](https://github.com/brajesh31). Include a link or a factual description of what happened and any context needed to review it. Please do not post private details in a public issue. For a security vulnerability, use the separate process in [SECURITY.md](SECURITY.md).

The maintainer will review reports, protect the reporter's privacy as far as reasonably possible, and decide on a proportionate response. Responses may include a request to stop, a warning, removal of content, temporary restrictions, or exclusion from project spaces. The maintainer may remove content or restrict participation when needed to protect people or keep the project usable. Retaliation against someone who raises a concern in good faith is not acceptable.

This policy is intended to support a safe and productive project community; it does not limit a person's ability to raise a concern through other appropriate channels.
